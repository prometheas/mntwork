# Define Repository Manifest and Workspace Record contracts

Type: prototype
Status: open

## Question

What minimal versioned schema should optional repository-local `.mntwork.toml` files contribute, how should CLI inputs and multiple repositories merge those contributions, what generated state belongs in the Workspace Record, how should a default cache-based data root and explicit external data root behave, and should any project-flake-derived configuration participate without forcing users to author a cross-repository manifest?
