# Bound what Repository Manifests may oblige

Repository Manifests describe what a project needs to run and never what the host trusts or how it is arranged, so runtime selection, data root, GC and retention policy, Shared Artifact Cache endpoints and keys, mount grants, credential grants, and Workspace identity are not manifest-expressible. Fields that remain are merged by declared per-field semantics rather than precedence—`floor`, `union`, `union-strict`, `unique`, `per-member`—so only genuine conflicts reach the user, and a field without a declared rule cannot ship.

Because manifests arrive from cloned repositories, a user-global Manifest Request Ceiling bounds both resource floors and privilege-expanding capability requests; crossing it stops preparation and requires purpose-named authorization such as `--accept-resource-request` or `--accept-capability-request`. The escape hatch is deliberately not `--force`, which ADR 0005 confines to content-safety checks and forbids from expanding targets and which ADR 0012 forbids from bypassing repository leases. Allowlist admission is evaluated before host availability because "never permitted" and "cannot be provided" have different remedies, and a non-TTY invocation fails with a stable exit code naming the authorizing flag instead of prompting.
